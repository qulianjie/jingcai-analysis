# 反馈循环设计

> 最后更新: 2026-05-26 | 状态: 生效中

---

## 一、反馈闭环概述

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  预分析      │────→│  赛后反馈    │────→│  模式学习    │
│  (日11:00)   │     │  (日13:00)   │     │  (反馈后)     │
└──────────────┘     └──────────────┘     └──────┬───────┘
       ↑                                         │
       │               ┌──────────────┐          │
       └───────────────│  模式匹配    │←─────────┘
                       │  (下次预分析) │
                       └──────────────┘
```

**循环周期**: 24小时（每日一次反馈→学习→匹配）

## 二、反馈流程（feedback.js）

### 2.1 执行时机

赛后12:00~13:00（cron触发），确保当日所有比赛已结束

### 2.2 步骤分解

| 步骤 | 操作 | 数据源 | 输出 |
|------|------|--------|------|
| 1 | 获取实际赛果 | zgzcw.com / trade.500.com | 比分数据 |
| 2 | 获取终盘赔率 | 重跑step146_extractor | 终盘胜/平/负 |
| 3 | 对比竞彩预测 | 读已存预测 | 正确/错误 |
| 4 | 对比让球预测 | 读已存预测 | 正确/错误 |
| 5 | 更新Notion | Notion API | 反馈字段写入 |
| 6 | 分组统计 | 自定义聚合 | 分组准确率 |
| 7 | 存档比分 | JSON文件 | scores_archive.json |

### 2.3 终盘赔率获取

**降级策略**:
1. 优先从 `match/` 目录读Step146数据
2. 无match目录时自动回退到 `matches_data.json` 读FID
3. 建临时目录调用step146_extractor.py
4. 完事后自动清理临时目录

**路径处理**: 使用 `__dirname`（非 `process.cwd()`），确保从任意目录执行路径正确

**编码依赖**: iconv-lite（500.com trade页面GBK编码，从td-team比分+data-matchnum编号）

## 三、学习流程（feedback_learner.py）

### 3.1 输入输出

| 输入 | 来源 | 格式 |
|------|------|------|
| `feedback.json` | feedback.js累积 | JSON数组 |
| `learned_patterns_v2.json` | 前次学习产出 | JSON |

| 输出 | 用途 | 格式 |
|------|------|------|
| `learned_patterns_v2.json` | pattern_matcher使用 | JSON（模式+准确率+置信度） |

### 3.2 算法

1. **特征提取**: 从反馈数据提取比赛特征（10个维度+精细数据）
2. **组合生成**: 自动生成一维→四维组合标签
3. **准确率计算**: 统计每个组合的命中率
4. **置信度校准**:
   - Wilson Score（小样本校正）
   - Bayesian Average（先验分布平滑）
5. **模式输出**: 保存≥2场样本、命中率≥60%的模式

## 四、模式匹配（pattern_matcher.py）

### 4.1 匹配流程

```
当日比赛特征
  │
  ├─→ 与learned_patterns_v2.json逐条匹配
  ├─→ 计算每个模式的dominance值
  ├─→ 筛选dominance ≥ 1.5的明确方向
  └─→ 去重后输出Notion备注
```

### 4.2 输出格式

```
📊 主方向胜 | 6维(N场) | 维度线索: 4维
📋 组合详情:
- [主胜-巅峰] lift=2.1x | 6/10(60%) | 特征: 胜赔≤1.6+平半盘+庄家看好
- [客胜-高胜率] lift=1.8x | 4/7(57%) | 特征: 胜负差≤0.5+让球≥1.0
```

## 五、持续改进机制

### 5.1 专家模式注入

人工维护 `expert_patterns.md`，记录已验证的盘路规律。

**匹配方式**: 按联赛/赔率/盘口/变化方向四维匹配，返回因子(0.0~1.0)

### 5.2 模式重建

**cron**: 每周一15:00

**执行**: `pattern_miner.py` 全量扫描所有历史训练数据，重建模式库

### 5.3 维度演进

| 阶段 | 算法 | 覆盖维度 |
|------|------|---------|
| 1-3维 | 穷举 | 所有组合 |
| 4-8维 | Apriori | 核心维度池，min_support=2 |
| 8维+ | 剪枝过滤 | 只保留高频项集 |
