## 三、备注格式规范

### 3.1 备注字段格式

每次更新时追加，不覆盖。格式：

```
[日期] 模式匹配结果
📊 方向标签 | 命中率 | 维度数 | 维度线索

📋 组合详情:
- [标签1] lift=2.1x | 胜6/10(60%) | 特征: 特征A+特征B+特征C
- [标签2] lift=1.8x | 胜4/7(57%) | 特征: 特征D+特征E

⚠️ 方向冲突
- 竞彩预测: 主胜 vs 模式匹配: 客胜优势
```

### 3.2 格式约束

- **必须带方向**（胜负/让球胜/让球负）+ 百分比 + 命中比 + 维度数
- 纯计数无方向的记录视为无效，不写入
- `dominance` 标签仅展示 ≥1.5 的明确方向
- 重复记录自动去重

## 四、同步规则

### 4.1 写入机制

**平台**: Windows Node.js → Notion REST API

**桥接**: WSL Python → Windows Python → Windows Node.js

**绕过GBK**: 使用 `@file temp` 方式传递数据，不直接在命令行传中文

### 4.2 降级策略

当某个预测字段的源文件不存在或格式异常时：
1. 尝试 `.md` → `.txt` 后缀降级
2. 尝试从 `meta.json` 补全
3. 仍缺失时跳过该字段写入

### 4.3 防重复

- 通过 `竞彩编号 + 日期` 查询已有页面
- 已存在的数据仅更新4个预测字段 + 反馈字段
- 备注字段追加不覆盖
